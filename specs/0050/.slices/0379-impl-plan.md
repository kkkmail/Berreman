# Step 0379 — impl plan

## Approach

Add `Study.residualWith context layout data vector : Result<ResidualVector, StudyForwardError>` as the last
declaration of `StudyForward.fs` (spec 0050 S11.2). It walks `data.runs` in order, and stops at the first error.

For each run:

1. Take its assignment, `layout.assignmentFor this context.kit.items run.experiment.name vector` (step 373).
2. Find its dark level. This is `data.darkOf` of the session of `layout.sessions` that lists the run (step 378), else
   `None`.
3. Bind the run: `run.experiment.boundWith context this assignment darkOpt` (step 375).
4. Take its weight, `this.residualWeightOf run.experiment.name bound.detectorItem` (step 365).
5. For each row, take `bound.predictedReadingOf row`, then `residualAgainst` of the row's measured reading (step 376).
   A settings row carries its reading; an observation row's reading is `RecordedMueller observation.measured`.
   Every entry is multiplied by the weight.

The vector is every row's `elements`, run after run and row after row, then every row's `throughputOpt`, in the same
order. That is `MuellerFitting.throughputResidualFor`'s layout (step 336). No cache, scaling or penalty is added.

## Risks

- **The ellipsometer run's pre-fit.** `detectorKindOf` reads the detector slot's library entry, not the item's model.
  An unbound slot reads as Intensity and would refuse a Ψ/Δ series. The ellipsometer bench therefore binds its
  detector slot to `PresetIds.detectorEllipsometer`.
- **The relative 1e-12 tolerance on the polarimeter study.** Step 375 already showed that `predictedReadingOf` and
  `createBerremanForward ... muellerOf` agree bit for bit. `ofScaled` at the zero vector is exactly the centre. So the
  match is expected to be exact.
- **Opening `OpticalConstructor.Optimization` in the test file** may shadow a name. If it does, qualify the call
  instead.
