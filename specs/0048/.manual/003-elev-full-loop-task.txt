EVERY BATCH

  Close exactly ONE row, in id order. Never skip ahead: each tier is typed
  against the ones before it (002 section 3, dependency order), and a lower
  assembly keeps a colliding name (R2).

  An elevate row: 002 section 5 is the procedure.
  1. Read the row, the rulings in its `rulings` (002 section 2), and AGENTS.md.
  2. Do the work, across every project in `compiled_by` and every project that
     references them, test projects included. A caller moves to the new name and
     never re-wraps.
  3. Delete or lower the known-findings entries the work cleared, in
     Elevation/elevation-known-findings.json, including those it cleared outside
     the row's files. Never add one, never re-record the list.
  4. Pass the gates (002 section 5):
     - build, with zero warnings from our code;
     - elevation (scoped, before the commit: it reads the working tree);
     - elevation-full instead, when the row renames across projects;
     - the test gates in the row's `gates`, selected by class on what the batch
       touched. unit-tests runs by class only, never whole.
     Counts never regress, and no number any test asserts changes.
  5. Write the note, flip the row (`state` done, `closedIn` the batch's round
     label, e.g. batch-007), and append the ledger rows.
  6. Commit.

  E001, E002, E043 and E044: 002 section 6, which binds over the row's own
  `task`.

  The row's note carries what 002 section 5 lists, in that order:
  - the counts before and after;

  - every stored-format change (also a line of
    specs/0048/.manual/stored-format-changes.md);

  - every public rename in a package of `packages` (also a row of
